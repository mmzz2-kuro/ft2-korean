# SS 엔딩 크레딧 PS1 편집본 이식 조사

## 확인 결과

PS1과 SS의 BE-HDR 리소스 `12`, `14`, `15`, `16`, `18`, `19`, `20`, `21`을 PNG로 복원해 비교한 결과, 원본 화면은 픽셀 단위로 동일했다. 따라서 PS1에서 확정한 한글 편집 PNG를 SS판에도 그대로 사용할 수 있다.

PS1의 실제 엔딩 표시는 리소스 23의 320x8 스트립 뱅크를 사용하지만 SS 리소스 23은 `0x13800`바이트의 별도 형식이다. PS1 런타임 프레임 도구를 SS에 그대로 적용할 수는 없다.

## 성우 크레딧 14/15 무손실 재배치

SS 리소스 14 편집본은 수평 반전 재사용을 포함해 275개의 고유 타일이 필요하지만 기존 용량은 250개다. 리소스 15는 기존 15섹터 중 14섹터만으로 편집본 409개 타일을 저장할 수 있다.

이에 14/15 경계를 1섹터 뒤로 이동했다.

- 테이블 엔트리 15: `213` → `214`
- 리소스 14: 9섹터 → 10섹터, 용량 282타일
- 리소스 15: 15섹터 → 14섹터, 용량 410타일
- 리소스 14 편집본: 275타일
- 리소스 15 편집본: 409타일
- 손실 병합: 0
- 변경 픽셀 오차: 0

이 처리는 `scripts/ss-fs2-palette-layer-resource.js`에 추가되어 SS 엔딩 GUI가 14와 15를 함께 적용할 때 자동 수행된다.

검증 파일:

- `tmp/ss-fs2-ending-resource-workflow/credit-14-15-test.bin`
- `tmp/ss-fs2-ending-resource-workflow/credit-14-15-test.report.json`

## 나머지 스태프 크레딧 용량

PS1 편집본을 SS 팔레트로 변환한 결과는 다음과 같다.

| 리소스 | 필요한 고유 타일 | 현재 용량 | 상태 |
|---:|---:|---:|---|
| 16 | 113 | 122 | 직접 적용 가능 |
| 18 | 208 | 186 | 22타일 부족 |
| 19 | 145 | 154 | 직접 적용 가능 |
| 20 | 202 | 186 | 16타일 부족 |
| 21 | 157 | 122 | 35타일 부족 |

18, 20, 21은 손실 타일 병합을 사용하지 않는 조건에서는 현재 리소스 경계 안에 들어가지 않는다. 인접 리소스들도 각각의 320x240 타일맵 때문에 최소 할당량이 필요하므로 단순 경계 이동만으로 세 리소스를 모두 수용할 수 없다. 이 세 리소스는 SS 로더의 별도 저장 영역 또는 런타임 참조 방식 조사가 필요하다.
