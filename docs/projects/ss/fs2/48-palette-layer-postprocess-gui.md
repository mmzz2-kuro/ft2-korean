# 48. 팔레트 레이어 추출·편집·재삽입 후처리 GUI

## 처리 위치

이 도구는 47단계의 최종 패치 GUI에 포함하지 않는다. 먼저 최종 SS 한국어판 Track 1을 만든 다음, 그 결과물을 입력으로 받아 팔레트형 시스템 UI 5건만 수정하는 독립 후처리 도구다.

```text
SS 원본 → 47단계 최종 패치 GUI → 한국어 최종 Track 1
                                  ↓
                         48단계 팔레트 후처리 GUI
                                  ↓
                    팔레트 UI까지 반영한 새 Track 1/CUE
```

입력 BIN을 직접 덮어쓰지 않으며 출력 BIN은 반드시 별도 파일로 만든다.

## 실행

```powershell
python tools/ss_fs2_palette_layer_gui.py
```

현재 정리된 최종 파일명을 기본값으로 사용한다.

```text
입력 Track 1: output/ss-fs2-korean-final-track1.bin
Track 2:      output/ss-fs2-korean-final-track2.bin
출력 Track 1: output/ss-fs2-korean-palette-final.bin
작업 폴더:    tmp/ss-fs2-palette-layer/
```

## 대상 리소스

| PS1 ID | SS ID | SS 크기 | 타일 용량 | 기본 추출 인덱스 |
|---:|---:|---:|---:|---|
| 828 | 714 | 512×208 | 267 | `1-2` |
| 1187 | 1073 | 304×208 | 256 | `1-2` |
| 1188 | 1074 | 512×240 | 419 | `224-231` |
| 1201 | 1087 | 512×144 | 667 | `21-22,224-231` |
| 1202 | 1088 | 304×208 | 96 | `5-10` |

기본값은 SS 최종 BIN에서 실제로 사용 중인 인덱스와 PS1 작업 기록을 바탕으로 한 시작값이다. 화면을 확인한 뒤 GUI에서 리소스별 인덱스를 바꿀 수 있다. 특히 여러 색 그라데이션이나 선택 상태는 한 인덱스가 아니라 연속 인덱스군을 사용할 수 있다.

인덱스 `0`도 선택할 수 있다. 0번은 다른 인덱스와 구분하기 위해 항상 단독 레이어로 처리한다.

```text
흰색 = 팔레트 인덱스 0 데이터
검은색 = 변경하지 않는 영역
```

`인덱스마다 PNG 분리`를 켜면 `0,1,2`처럼 입력해도 자동으로 `idx0`, `idx1`, `idx2` 파일로 나뉜다. 분리를 끈 상태에서는 0과 다른 인덱스를 한 이미지에 합칠 수 없다. 인덱스 2도 흰색으로 표시되기 때문에 합치면 어느 인덱스인지 구분할 수 없기 때문이다.

## 작업 순서

1. 최종 한국어 Track 1과 Track 2를 선택한다.
2. 필요한 SS 리소스와 팔레트 인덱스를 체크한다.
3. `1. 레이어 추출`을 누른다.
4. 작업 폴더의 `*-edit.png`를 이미지 편집기로 수정한다.
5. `context.png`로 위치를 확인하고 `legend.png`/`legend.tsv`의 지정 RGB만 사용한다.
6. 이미지 크기와 파일명을 유지한다.
7. `2. 편집 레이어 재삽입`을 누른다.
8. 새 BIN/CUE를 에뮬레이터 또는 실기에서 확인한다.

`인덱스마다 PNG 분리`가 켜져 있으면 한 팔레트 인덱스당 편집 PNG 하나가 생성된다. PS1 도구와 마찬가지로 검은 픽셀은 원본 인덱스를 유지하고, 지정 RGB와 일치하는 픽셀만 해당 인덱스로 변경한다.

## 안전 처리

- 처리 가능한 리소스 ID를 `714, 1073, 1074, 1087, 1088`로 제한한다.
- SS 실행 파일의 리소스 테이블에서 각 LBA와 할당 길이를 매번 읽는다.
- 원본 SS 리소스의 팔레트, 헤더, 화면 크기와 할당 길이는 보존한다.
- 편집된 전체 인덱스 화면을 8×8 타일로 다시 중복 제거한다.
- 고유 타일 수가 원래 용량을 넘으면 BIN을 수정하지 않고 실패한다.
- 변경한 모든 Mode 1 섹터의 EDC/ECC를 다시 계산한다.
- 완료 후 원본 대비 Mode 1 검증을 실행하고 JSON 보고서를 쓴다.
- 출력 CUE는 새 Track 1과 선택한 Track 2를 참조한다.

## 검증 결과

기준 입력:

```text
output/ss-fs2-korean-final-track1.bin
SHA-256 EB9DE6FC464732CED9B2FAA3E1E5DB3BB2B48C50EC164F0C519FCC1229507C69
```

5개 리소스를 전부 raw 팔레트 인덱스 PGM으로 추출했다. 편집 없이 그대로 적용하는 무변경 왕복 시험 결과는 다음과 같다.

| 항목 | 결과 |
|---|---:|
| 처리 대상 | 5개 |
| 변경 섹터 | 0 |
| 변경 user bytes | 0 |
| 출력 SHA-256 | 입력과 완전 일치 |
| 잘못된 Mode 1 EDC/ECC | 0 |

이 검증으로 추출과 재삽입 사이에서 사용자가 수정하지 않은 데이터가 임의로 바뀌지 않는 것을 확인했다. 실제 번역 이미지의 타일 용량과 게임 화면 확인은 각 편집본을 만든 뒤 리소스별로 수행한다.
