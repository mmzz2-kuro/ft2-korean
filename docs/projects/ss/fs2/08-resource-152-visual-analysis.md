# 리소스 152 타일 시각 분석

## 목적

`07-video-and-font-leads.md`에서 확인한 리소스 152가 글꼴 원본인지, UI용 타일인지, 또는 변환 전 중간 데이터인지 판별하기 위해 같은 바이트열을 여러 Saturn 타일 형식으로 펼쳐 보았다.

- 이미지: `ss/others/Farland Saga - Toki no Michishirube (Japan) (Track 1).bin`
- 파일 1 내부 섹터: `3780..3789`
- 파일 1 상대 오프셋: `0x762000`
- 크기: `0x5000` bytes
- 일반 리소스 ID: `152`
- 런타임 적재 주소: `0x060BAC30`
- 적재 호출 지점: `0x0603638C`

## 재현 도구

```powershell
node scripts/ss-fs2-visualize-resource.js
```

출력은 `output/ss-fs2-resource-152-tiles.html`이다. 기본 입력 경로, 리소스 ID, 출력 경로는 각각 명령행 인수 1~3으로 바꿀 수 있다.

뷰어는 한 페이지에 256개 타일을 표시하며 1bpp 8×8, 4bpp 8×8, 8bpp 8×8, 4bpp 16×16 해석을 전환한다. 색상은 실제 CRAM 팔레트가 아니라 인덱스 크기만 표현하는 단색 명암이므로 형태 판별용이다.

## 계량 결과

| 해석 | 전체 타일 | 고유 타일 | 전부 0인 타일 | 단일 바이트 반복 타일 |
| --- | ---: | ---: | ---: | ---: |
| 1bpp 8×8 | 2,560 | 2,169 | 392 | 392 |
| 4bpp 8×8 | 640 | 543 | 98 | 98 |
| 8bpp 8×8 | 320 | 272 | 49 | 49 |
| 4bpp 16×16 | 160 | 137 | 24 | 24 |

네 해석에서 빈 타일 비율이 약 15%로 반복되는 것은 동일한 0 바이트 구간을 서로 다른 크기로 묶은 결과다. 이것만으로 특정 bpp를 확정할 수는 없다.

원본 전체 통계:

- 크기: 20,480 bytes
- 서로 다른 바이트 값: 214개
- 0 바이트: 3,850개
- Shannon entropy: 약 5.996 bits/byte

## 관찰과 판정

현재 단계에서는 리소스 152를 **직접 표시 가능한 고정폭 글꼴 원본으로 확정하지 않는다**.

- 어느 해석에서도 고유 타일 비율이 약 84.7%로 높다.
- 값의 종류가 214개이고 엔트로피도 1bpp 원본치고 높다. 다만 4bpp packed 자료에서는 nibble 조합이 다양할 수 있으므로 이 통계만으로 4bpp를 배제할 수 없다.
- 로더 직후 데이터가 `0x0601B00C(buffer, 5, 0)`로 전달된다. 후속 분석 결과 이 함수는 `0x1000`-byte 블록을 SCSP 사운드 RAM으로 보내는 스트림 초기화 함수로 확인됐다.
- 리소스 크기 `0x5000`은 전달된 블록 수 `5`와 정확히 일치한다.

따라서 리소스 152는 **SCSP 스트림 오디오 자료**로 재분류하며 글꼴 후보에서 제외한다. 타일 시각화는 잘못된 후보를 제거한 음성 대조 결과로 보존한다.

## 다음 조사

실제 소비 함수 `0x0601AEAC`의 전송 경로는 `10-audio-stream-ring-buffer.md`에서 규명했다. 폰트 조사는 리소스 152와 분리해 다시 진행한다.

1. 리소스 152의 구체적인 오디오 형식을 판별한다.
2. VDP2 PNT 갱신 코드의 source 포인터를 새로 추적한다.
3. 별도 그래픽 payload가 확인되면 해당 바이트열을 다시 펼친다.
4. 글자 모양이 확인될 때에만 문자 코드→글리프 인덱스 루틴을 역추적한다.
