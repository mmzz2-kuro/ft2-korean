# 36. 예외 8bpp UI 무손실 재패킹 PoC

## 시도한 방식

35단계의 후보 3개에 대해 다음 순서로 SS 원본 기반 합성을 시도했다.

1. PS1 원본 화면과 최신 PS1 화면을 raw palette index 픽셀로 복원한다.
2. 두 화면에서 값이 달라진 픽셀만 번역 변경으로 간주한다.
3. 해당 픽셀을 같은 좌표의 SS 원본 화면에 합성한다.
4. 완성 화면을 8×8 타일로 정확히 분할하고 중복 타일만 제거한다.
5. 고유 타일 수가 SS 리소스 용량 이하일 때만 기록한다.

손실 타일 병합과 유사 타일 대체는 허용하지 않았다.

도구와 보고서:

- `scripts/ss-fs2-build-behdr-exception-patch.js`
- `output/ss-fs2-korean-behdr-ui-exceptions.report.json`

| 1187 | 1073 | 5,365 | 267 | 256 | 11 | 제외 |
| 1188 | 1074 | 10,095 | 493 | 419 | 74 | 제외 |

세 항목 모두 무손실 용량을 초과했으므로 실제 SS 리소스는 하나도 변경하지 않았다.

`output/ss-fs2-korean-behdr-ui-exceptions.bin`은 빌드 절차에서 생성됐지만 적용 수가 0이라 입력 파일 `output/ss-fs2-korean-behdr-ui-latest.bin`과 내용이 같다. 테스트 기준은 계속 `ss-fs2-korean-behdr-ui-latest.cue`다.

## 초과 원인

최신 PS1 리소스의 변경 픽셀에는 단순한 글자뿐 아니라 PS1 작업 과정에서 편집된 여러 팔레트 인덱스 레이어가 포함된다. 이를 배경 구성이 다른 SS 화면에 좌표 단위로 전부 합성하면 PS1 타일 패턴과 SS 고유 배경 타일 패턴이 함께 필요해져 고유 타일 수가 증가한다.

기존 TSV에는 이 세 항목의 `patch_regions`가 비어 있어 자동으로 글자 영역만 구분할 정보가 없다.

## 다음 방향

전체 픽셀 차이를 옮기는 방법은 보류한다. 다음 단계에서는 PS1 편집 자산과 팔레트 레이어 작업물을 이용해 실제 한글 글자 영역을 찾아낸 뒤, 그 영역만 SS 화면에 적용했을 때의 타일 예산을 다시 계산한다. 영역을 확정하기 전에는 손실 병합을 사용하지 않는다.
