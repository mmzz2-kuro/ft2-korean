# 32. Big-endian header UI 리소스 대응 조사

## 목적

PS1판에서 편집한 8bpp 타일형 UI 이미지 66개를 새턴판에 옮기기 전에 리소스 대응과 원본 동일성을 확인한다. 이 계열은 리소스 선두에 폭·높이·타일 데이터 위치를 big-endian으로 기록하며, 기존 `be-hdr-ui` 작업 흐름으로 편집되어 있다.

## 입력

- SS Track 1: `ss/others/Farland Saga - Toki no Michishirube (Japan) (Track 1).bin`
- PS1 데이터: `ps1/SLPS-01903/FS2_FILE.DAT`
- PS1 실행 파일: `ps1/SLPS-01903/SLPS_019.03`
- 편집표: `trDatas/be-hdr-ui-workflow/be-hdr-ui-translation.tsv`
- 조사 도구: `scripts/ss-fs2-map-behdr-ui.js`
- 기계 판독 결과: `output/ss-fs2-behdr-ui-map.json`

## 대응 규칙

앞서 확인한 UI/이름 리소스와 동일하게 다음 규칙이 성립한다.

```text
SS resource ID = PS1 resource ID - 114
```

대상 범위는 다음과 같다.

- PS1 `811..828` → SS `697..714`: 18개
- PS1 `1170..1217` → SS `1056..1103`: 48개
- 합계: 66개

## 원본 비교 결과

PS1 리소스 시작/끝 섹터와 SS 리소스 시작/끝 LBA로 계산한 할당 영역 전체를 비교했다.

| 구분 | 개수 |
|---|---:|
| 전체 대상 | 66 |
| 할당 크기 동일 | 62 |
| 할당 영역 바이트 완전 동일 | 61 |
| PS1 편집 PNG 존재 | 58 |

완전히 동일하지 않은 5개는 다음과 같다.

| PS1 ID | SS ID | PS1 섹터 | SS 섹터 | 판정 |
|---:|---:|---:|---:|---|
| 828 | 714 | 10 | 10 | 크기는 같지만 내용이 다름 |
| 1187 | 1073 | 8 | 9 | 크기와 내용이 다름 |
| 1188 | 1074 | 14 | 15 | 크기와 내용이 다름 |
| 1201 | 1087 | 29 | 22 | 크기와 내용이 다름 |
| 1202 | 1088 | 3 | 4 | 크기와 내용이 다름 |

따라서 PS1에서 패치한 리소스를 새턴판에 그대로 이식할 수 있는 범위는, 원본이 완전히 같고 편집 PNG도 존재하는 **54개**다. 위 5개는 화면 구성 또는 타일 예산이 다를 수 있으므로 직접 이식 대상에서 제외한다.

## 편집 PNG가 없는 항목

다음 8개는 기존 작업표에 `replacement_png`가 없다.

```text
PS1 1179, 1180, 1190, 1202, 1214, 1215, 1216, 1217
SS   1065, 1066, 1076, 1088, 1100, 1101, 1102, 1103
```

`1179`, `1180` 등 이름 표를 참조하는 화면은 앞 단계의 이름 테이블 패치로 이미 한글화되는 부분이 있다. 편집 이미지가 없는 항목은 이번 단계에서 임의 생성하지 않는다.

## 결론과 다음 작업

1. 원본 완전 동일 + 편집 PNG 존재 조건을 만족하는 54개만 1차 안전 빌드에 적용한다.
2. PS1 원본의 raw index 화면과 편집 PNG를 결합해 타일 데이터를 다시 패킹한다.
3. 패킹 후 리소스 크기가 원래 SS 할당 범위를 넘지 않는지 검사한다.
4. 예외 5개는 SS 원본을 직접 추출해 별도의 화면별 비교·편집 대상으로 남긴다.
5. 결과는 현재 검증된 `ss-fs2-korean-names.bin` 위에 누적하고 Mode 1 EDC/ECC를 재검증한다.
