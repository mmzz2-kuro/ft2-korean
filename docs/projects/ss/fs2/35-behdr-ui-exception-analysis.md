# 35. 8bpp UI 예외 리소스 5개 분석

## 목적

PS1과 SS의 할당 영역이 달라 34단계에서 제외한 5개를 화면 구조 단위로 비교했다. 최신 PS1 데이터는 `output/patched-farland-saga-logo.bin`에서 추출한 DAT를 사용했다.

분석 도구와 결과:

- `scripts/ss-fs2-analyze-behdr-exceptions.js`
- `output/ss-fs2-behdr-exceptions.json`

## 비교 결과

| PS1 ID | SS ID | PS1 화면 | SS 화면 | PS/SS 타일 용량 | 팔레트 동일 | 최신판 변경 픽셀 | 판정 |
|---:|---:|---:|---:|---:|---|---:|---|
| 828 | 714 | 512×208 | 512×208 | 267 / 267 | 예 | 8,321 | SS 기준 재패킹 후보 |
| 1187 | 1073 | 304×208 | 304×208 | 224 / 256 | 예 | 5,365 | SS 기준 재패킹 후보 |
| 1188 | 1074 | 512×240 | 512×240 | 387 / 419 | 예 | 10,095 | SS 기준 재패킹 후보 |
| 1201 | 1087 | 512×240 | 512×144 | 867 / 667 | 예 | 28,084 | 화면 높이가 달라 직접 이식 불가 |
| 1202 | 1088 | 304×216 | 304×208 | 63 / 96 | 예 | 0 | 최신 PS1판에 변경 없음 |

`타일 용량`은 리소스 할당 끝까지 사용할 수 있는 64바이트 8×8 타일 수다.

## 해석

### PS1 828 → SS 714

화면 크기와 타일 용량, 팔레트가 모두 같다. 다만 원본 표시 픽셀은 완전히 같지 않으므로 PS1 패치 리소스 전체를 복사하면 안 된다. PS1 원본과 최신 패치의 픽셀 차이만 SS 원본 화면에 합성한 후 SS 타일맵을 기준으로 재패킹하는 방식이 적합하다.

### PS1 1187 → SS 1073, PS1 1188 → SS 1074

화면 크기와 팔레트가 같고 SS 쪽 타일 용량이 각각 32개 더 많다. 따라서 차이 픽셀 합성 후 용량 검사를 통과할 가능성이 높다. 원본 배경 차이를 보존하기 위해 이 두 항목도 전체 리소스 복사가 아니라 SS 원본 기반 재패킹이 필요하다.

### PS1 1201 → SS 1087

SS판 화면 높이가 96픽셀 짧고 타일맵 구성도 다르다. 좌표 차이와 어떤 영역이 생략 또는 이동됐는지 화면별 대응 조사가 필요하다. 자동 합성 대상에서 제외한다.

### PS1 1202 → SS 1088

화면 높이가 8픽셀 다르지만 최신 PS1 통합판의 표시 픽셀은 PS1 원본과 같다. 옮길 한글 변경이 없으므로 현재 단계에서 처리할 필요가 없다.

## 다음 작업

1. 828/1187/1188에 대해 `PS1 원본 → 최신 PS1` 픽셀 차이 마스크를 만든다.
2. 그 차이만 SS 원본 인덱스 화면에 합성한다.
3. SS 고유 타일맵과 타일 용량으로 무손실 재패킹한다.
4. 용량을 초과하면 자동 손실 병합을 적용하지 않고 해당 리소스를 보류한다.
5. 성공한 항목만 최신 통합판에 누적하고 EDC/ECC를 검증한다.
