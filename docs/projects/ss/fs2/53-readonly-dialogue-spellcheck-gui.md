# 53. 읽기 전용 대사 맞춤법·표시 QA GUI

## 목적

`dialogue-translation.tsv`의 한국어 대사 전체를 한 번에 검사하되 원본 TSV를 수정하지 않는 독립 GUI를 추가했다. 자동 수정은 하지 않으며 의심 항목과 제안, 사유, 앞뒤 문맥만 보여준다.

## 실행

```powershell
python tools/dialogue_spellcheck_gui.py
```

기본 입력은 `trDatas/dialogue-workflow/dialogue-translation.tsv`이고 기본 폭 측정 글꼴은 `font/gulim.ttc`다. `전체 검사`를 누르면 한국어가 입력된 모든 행을 한 번에 검사한다.

## 검사 항목

- 확실도가 높은 표준어·띄어쓰기·어미 규칙
- 히라가나·가타카나 잔존
- 탭, 줄 끝 및 문장 중간 연속 공백
- 3줄 초과 대사
- 행별 `font_size`를 사용한 196px 안전 폭 초과 후보

고유명사와 캐릭터 말투를 일반 사전으로 강제 교정하지 않도록 규칙은 보수적으로 구성했다. 공백, 줄 수, 표시 폭처럼 화면 배치 의도일 수 있는 항목은 `검토` 등급으로 분리한다. 기본 필터는 `확실`이며 필요할 때 등급을 `전체`로 바꿔 형식 후보도 확인한다.

## 결과 확인

결과 목록에는 등급, 유형, 메시지 ID, 줄 번호, 현재 문장, 제안, 사유가 표시된다. 항목을 선택하면 아래 읽기 전용 문맥 창에 이전·현재·다음 대사와 검사 제안이 함께 나온다.

검색어, 유형, 등급으로 결과를 좁힐 수 있다. 현재 표시 중인 결과는 JSON 또는 UTF-8 BOM CSV 보고서로 별도 저장할 수 있다.

## 원본 보존

- 원본 TSV를 쓰는 코드가 없다.
- 제안을 TSV에 반영하는 버튼이 없다.
- JSON/CSV 저장은 사용자가 선택한 새 보고서 경로만 대상으로 한다.
- 실제 수정 여부와 문구는 사용자가 기존 대사 GUI에서 별도로 결정한다.

## 최초 전수 검사

- 전체 TSV 행: 2,697
- 한국어가 채워진 행: 2,665
- 보수적 맞춤법 규칙 적중: 39건
- 일본어 가나 잔존 행: 0건
- 3줄 초과 검토 후보: 42건
- 전체 맞춤법·형식 후보: 932건

전체 후보가 많은 주된 이유는 기존 대사에 화면 정렬용 줄 끝·연속 공백이 많이 남아 있기 때문이다. 이 항목은 오류로 확정하지 않고 `검토/공백`으로 분류하며, 기본 `확실` 필터에서는 숨긴다.
