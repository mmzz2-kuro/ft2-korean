# 세가 새턴판 파랜드 사가 2 초기 조사

## 범위

이 문서는 `ss/others`의 트랙 분리 BIN/CUE 세트를 기준으로 수행한 첫 정적 조사 결과를 기록한다. 게임 리소스의 의미를 아직 확정하는 단계가 아니라, 원본 식별, 디스크 구조, ISO9660 파일 배치, 부트 파일 및 대형 데이터 파일의 성격을 판정하는 단계다.

분석 입력:

| 파일 | 크기 | SHA-256 |
| --- | ---: | --- |
| `Farland Saga - Toki no Michishirube (Japan).cue` | 256 | `C3996ABEAF4A8D1EB82FE6F5FDDDD1319C9A32A6DB2AD9E1A05212668D650EF0` |
| `Farland Saga - Toki no Michishirube (Japan) (Track 1).bin` | 516,419,232 | `267CB97B787E4F3C804CBCB0495977C7F3B309513CA15F918A9C3C6D18996D02` |
| `Farland Saga - Toki no Michishirube (Japan) (Track 2).bin` | 3,880,800 | `1E3504C775B34E839B52C9DEA95C40D51E3F4DCDAE82CC88A11413D6ED301741` |

두 BIN을 CUE에 적힌 순서대로 연결한 바이트열은 CloneCD IMG와 완전히 일치한다. 연결 데이터와 IMG의 SHA-256은 모두 다음과 같다.

```text
E5DDD15D8638FBDA193312241709FD4245206DD2806C08BE0EC65A0235A28B01
```

## 트랙 구조

| 구간 | 형식 | 파일 내 섹터 | 디스크상 의미 |
| --- | --- | ---: | --- |
| Track 1 | `MODE1/2352` | 219,566 | LBA 0부터 시작하는 데이터 트랙 |
| Track 2 INDEX 00 | AUDIO | 150 | 2초 pregap |
| Track 2 INDEX 01 | AUDIO | 1,500 | LBA 219,716부터 시작하는 20초 CDDA |

두 BIN 모두 2352바이트의 정수 배다. Track 1과 Track 2 파일을 합치면 221,216섹터로 CloneCD IMG의 전체 섹터 수와 같다.

## 새턴 및 ISO 식별 정보

| 항목 | 값 |
| --- | --- |
| 하드웨어 ID | `SEGA SEGASATURN` |
| 메이커 ID | `SEGA TP T-325` |
| 제품 번호 | `T-32511G` |
| 버전 | `V1.000` |
| 빌드 날짜 | `19981104` |
| 지역 | `J` |
| 게임명 | `FARLANDSAGA2` |
| ISO 시스템 ID | `SEGA SEGASATURN` |
| ISO 볼륨 ID | `FARLAND_SAGA2` |
| PVD | LBA 16 |
| 루트 디렉터리 | LBA 20, 2,048 bytes |

IP 영역의 `0xF0`에는 big-endian 값 `0x06010000`이 있다. ISO 파일 `0`의 시작 코드가 이 주소를 기준으로 링크된 것으로 보이는 리터럴을 포함하므로, 현재는 이를 최초 실행 파일의 로드 주소로 판정한다. 파일 `0`의 시작 바이트도 유효한 SH-2 명령열 형태다.

## ISO9660 파일 지도

목록은 다음 명령으로 재현할 수 있다.

```powershell
node scripts/ss-fs2-list-iso.js "ss/others/Farland Saga - Toki no Michishirube (Japan) (Track 1).bin"
```

| 경로 | LBA | 크기 | 섹터 | 역할 또는 현재 판정 |
| --- | ---: | ---: | ---: | --- |
| `0` | 21 | 319,524 | 157 | SH-2 메인 실행 파일 후보 |
| `1` | 178 | 448,993,280 | 219,235 | 게임 리소스 컨테이너 후보 |
| `FS2_CPY.TXT` | 219,413 | 21 | 1 | 저작권 문자열 |
| `FS2_ABS.TXT` | 219,414 | 2 | 1 | `2E 1A` |
| `FS2_BIB.TXT` | 219,415 | 2 | 1 | `2E 1A` |
| `CDDA1` | 219,716 | 3,072,000 | 1,500 | Track 2 INDEX 01의 CDDA를 가리키는 엔트리 |

주요 배치 관계:

- 파일 `0`은 LBA 21부터 157섹터를 점유하고 다음 파일 `1`의 LBA 178 직전에 끝난다.
- 파일 `1`의 크기는 정확히 219,235 × 2,048 bytes다.
- 파일 `1`은 LBA 178부터 219,413 직전까지 이어진다.
- 세 개의 작은 텍스트 파일 뒤에는 Track 1 끝까지 예약 또는 패딩 구간이 있다.
- `CDDA1`의 extent는 Track 1 BIN 범위를 벗어나지만 전체 디스크의 Track 2 INDEX 01과 정확히 일치한다. 손상된 파일 범위가 아니라 오디오 트랙을 ISO 엔트리로 노출한 구조다.
- PVD의 volume space size는 데이터 트랙 길이 219,566이 아니라 전체 디스크 길이 221,216으로 기록되어 있다.

`FS2_CPY.TXT` 내용:

```text
(c) TGL 1997, 1998\r\n\x1A
```

## 파일 `0`: 실행 파일 후보

파일 시작은 다음 SH-2 명령 및 주소 리터럴 형태를 보인다.

```text
D0 04 6F 03 D0 02 40 2B 00 09 00 09 00 09 00 09
06 01 00 34 06 0F FC 00 00 09 00 09 00 09 00 09
```

현재 판정:

- 별도 실행 파일 헤더 없이 raw SH-2 코드로 시작한다.
- IP 영역의 로드 주소 후보 `0x06010000`과 파일 내부 리터럴 `0x06010034`, `0x06010050` 등이 일관된다.
- 따라서 Ghidra/IDA 등에는 우선 SH-2 big-endian, base address `0x06010000`으로 로드하는 것이 타당하다.
- 전체 파일의 ASCII run을 조사했을 때 file offset `0x32831`에서 `CD001`, `0x433D0`에서 `CDC Version 1.22 1997-02-27`이 확인된다. ISO9660 판독 코드와 세가 CD 통신 라이브러리 코드가 실행 파일에 포함된 근거다.
- `FS2`, `CDDA1` 같은 명시적인 파일명 문자열은 확인되지 않았다. 파일을 숫자 ID, 디렉터리 순서 또는 LBA로 접근할 가능성을 우선 조사한다.
- 정확한 진입점, BSS 초기화 범위, 파일 `1` 로더 함수와 문자열/리소스 참조는 아직 확인하지 않았다.

## 파일 `1`: 리소스 컨테이너 후보

파일 `1`의 첫 16바이트는 다음과 같다.

```text
00 00 00 25 00 00 00 03 00 00 1B 10 00 00 02 F0
```

이를 big-endian 32-bit 필드 네 개로 읽으면 다음과 같다.

| 필드 | 값 |
| --- | ---: |
| 1 | 37 |
| 2 | 3 |
| payload size 후보 | `0x1B10` |
| 4 | `0x2F0` |

이 헤더와 뒤따르는 데이터는 PS1판 `FS2_FILE.DAT`의 시작과 같다. 두 파일을 byte-for-byte 비교하면 컨테이너 offset `0x83802`에서 처음 달라진다.

| 비교 항목 | 세가 새턴판 파일 `1` | PS1판 `FS2_FILE.DAT` |
| --- | ---: | ---: |
| 전체 크기 | 448,993,280 | 244,678,656 |
| 2,048-byte 섹터 수 | 219,235 | 119,472 |
| 동일 prefix | `0x83802` bytes | `0x83802` bytes |
| 첫 차이 | `0x04` | `0x00` |

현재 판정:

- 두 버전은 컨테이너의 기본 블록 형식과 초기 리소스 일부를 공유한다.
- 시작 헤더가 같은 것만이 아니라 약 526 KiB의 prefix가 일치하므로, PS1판에서 만든 블록 스캐너와 그래픽 판독 도구를 구조 확인에 재활용할 가치가 높다.
- 첫 차이 이후의 리소스 ID, 순서, 실행 시 해석이 동일하다는 보장은 없다.
- SS판 파일 `1`은 PS1판보다 약 195 MiB 크므로 추가 그래픽, 음성, 영상 또는 플랫폼별 데이터의 위치를 별도로 지도화해야 한다.

## 현재까지 확정한 것과 남은 것

확정:

- 분석 입력 BIN/CUE는 정상이고 CloneCD IMG와 같은 디스크다.
- ISO9660 전체 루트 엔트리와 LBA/크기를 읽을 수 있다.
- 파일 `0`은 `0x06010000`에 맞춰진 raw SH-2 실행 코드로 판단된다.
- 파일 `1`은 PS1판 `FS2_FILE.DAT`와 형식 및 초기 데이터를 공유하는 대형 컨테이너다.
- 오디오 트랙의 위치와 `CDDA1` 엔트리가 서로 일치한다.

미확정:

- 파일 `0`의 정확한 진입점 및 섹션 구분
- 파일 `1`의 전체 엔트리 테이블과 SS 전용 구간
- 대사 스크립트 위치와 문자 인코딩
- 폰트 및 VDP1/VDP2 렌더링 경로
- 파일 크기 변경 시 하드코딩된 LBA의 존재 여부
- 원본 Mode 1 EDC/ECC에 의도적인 비표준 섹터가 있는지 여부

## 다음 조사 순서

1. 파일 `0`을 무손실 추출하고 SH-2 base `0x06010000` 기준으로 함수와 리터럴 참조를 지도화한다.
2. 파일 `0`에서 ISO 파일명 `0`, `1`, `CDDA1` 및 CD 읽기 루틴의 교차 참조를 찾는다.
3. 파일 `1`을 직접 sector view로 읽는 스캐너를 만들어 PS1 도구가 가정한 `0x800` 정렬 블록을 검증한다.
4. `0x83802` 첫 차이 주변과 이후 블록을 비교해 공통/SS 전용 리소스 경계를 찾는다.
5. 화면에서 확인 가능한 일본어 문구를 기준으로 대사와 UI 텍스트 후보를 좁힌다.
