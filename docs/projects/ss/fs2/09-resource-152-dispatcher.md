# 리소스 152 디스패처 분석

## 결론

`0x0601B00C`는 리소스 152를 한 번 변환하는 압축 해제 함수가 아니다. 후속 분석에서 이 함수는 데이터 포인터, 4KB 블록 수, SCSP 목적지 링의 초기 슬롯을 등록하는 **오디오 스트림 초기화 함수**로 확정됐다. 자세한 전송 경로는 `10-audio-stream-ring-buffer.md`를 참조한다.

따라서 리소스 152의 두 번째 인자 `5`를 bpp나 압축 방식으로 해석했던 가설은 폐기한다. `0x5000 = 5 × 0x1000`이며, 실제 소비 함수는 한 번에 `0x1000` bytes를 SCSP 사운드 RAM으로 복사한다.

## 함수 입력

호출 규약은 다음과 같이 좁혀졌다.

```c
audio_stream_init(void *data, uint8_t block_count, uint32_t initial_slot);
```

| 레지스터 | 의미 | 근거 |
| --- | --- | --- |
| `R4` | 데이터 포인터 | 함수 초반 `R8`에 보존한 뒤 전역 포인터 두 곳에 기록 |
| `R5` | 8-bit 블록 수 | `EXTU.B R5,R11` 후 두 전역 halfword에 기록 |
| `R6` | 초기 링 슬롯 | `R9`에 보존해 전역 long/halfword에 기록 |

`R5`는 포인터가 아니다. opcode `0x6B5C`는 `MOV.B @R5,R11`이 아니라 `EXTU.B R5,R11`이다. 호출부의 작은 상수 `4`, `5`, `7`은 각각 전송할 4KB 블록 수다.

## `0x0601B00C`의 상태 등록

함수는 먼저 기존 상태 포인터를 검사하고, 활성 상태가 있으면 `0x06056C80(0)`을 호출한다. 이후 입력값을 다음 전역 영역에 복제한다.

| 전역 주소 | 기록 값 |
| ---: | --- |
| `0x06061FB8` | `R4` 데이터 포인터 |
| `0x06061FC4` | `R4` 데이터 포인터 |
| `0x06061FD0` | zero-extended `R5` 블록 수 |
| `0x06061FDC` | zero-extended `R5` 대기 블록 수 |
| `0x06061FCC` | `R6` 부가 인자 |
| `0x06061FC0` | `R6`의 하위 halfword |
| `0x06061FD2` | 0으로 초기화 |

두 포인터와 두 블록 수는 현재 스트림 상태와 대기 상태를 보관한다.

등록 후 `0x0601AEAC`를 즉시 한 번 호출한다. 이 함수는 source에서 `0x1000` bytes를 SCSP 사운드 RAM 링 버퍼로 복사하고 source를 전진시키며 남은 블록 수를 감소시킨다.

## 보조 호출 `0x06056A8C`

`0x0601B00C`는 스택에 두 개의 작은 기술자 구조를 만들고 마지막에 다음 호출을 수행한다.

```c
sub_06056A8C(&local_0, &local_8);
```

`0x06056A8C` 자체는 다음 동작만 하는 얇은 래퍼다.

1. 두 번째 구조의 `+0x0A` byte를 0으로 설정
2. `0x06056ACC(first, second)` 호출
3. 반환값을 `EXTU.B`로 정규화해 반환

이 경로는 리소스 버퍼를 직접 인자로 받지 않는다. 리소스 포인터는 앞서 전역 상태에 등록되어 있다. 따라서 이 호출만을 근거로 리소스 152가 즉시 압축 해제 또는 VRAM 변환된다고 볼 수 없다.

`0x06056ACC`는 `0x06061980`, `0x060619A4`의 공용 상태를 사용하고 여러 유효성 검사를 수행하는 더 큰 기반 루틴이다. 현재로서는 동기화·명령 제출·상태 머신 실행 중 어느 것인지 확정하지 않는다.

## 전체 호출 목록

실행 파일에서 `0x0601B00C`를 PC-relative literal로 불러 `JSR`하는 지점은 7곳이다.

| 호출 지점 | `R5` 블록 수 | 비고 |
| ---: | ---: | --- |
| `0x0601B11E` | 호출자에서 전달 | 내부 래퍼 |
| `0x0601B1A0` | 호출자에서 전달 | 내부 래퍼 |
| `0x0601B24C` | 호출자에서 전달 | 내부 래퍼 |
| `0x06033FB6` | 4 | `0x060BAC30` 참조 구간 |
| `0x0603403A` | 4 | `0x060BAC30` 참조 구간 |
| `0x06034584` | 7 | 상위 화면 처리 함수 안의 별도 사운드 호출 |
| `0x060363BA` | 5 | 리소스 152를 적재한 뒤의 호출 |

마지막 네 호출은 동일한 Work RAM 버퍼 `0x060BAC30`을 사운드 자료의 임시 적재 버퍼로 사용한다. `R5`는 각 적재 자료의 `0x1000`-byte 블록 수다.

## 리소스 152 재분류

리소스 첫 부분의 불규칙한 byte 분포는 그래픽이 아니라 오디오 스트림 데이터였기 때문에 나타난 것이다. 구체적인 PCM/ADPCM 형식은 아직 확인하지 않았다.

현재 분류는 SCSP 링 버퍼로 전송되는 오디오 스트림 자료다. 직접 표시 가능한 글꼴/타일 가설은 폐기한다.

- 리소스 152의 PCM/ADPCM 형식과 재생 파라미터
