# PS1 엔딩 resource 12 적용 이상 조사

## 확인 결과

`output/patched-farland-saga-ending.bin`의 resource 12는 입력 대비 655바이트가 변경되어 적용 단계 자체가 생략된 것은 아니었다. 그러나 최종 BIN에서 다시 추출한 화면에는 오른쪽 흰 선만 남고 문자 타일은 사라져 있었다. 따라서 해당 결과물은 정상 적용본이 아니다.

## 중복 리소스 조사

- 원본 resource 12의 8,192바이트 할당 영역은 PS1 `FS2_FILE.DAT` 전체에서 한 번만 존재한다.
- 실제 320×240 화면을 디코딩해 비교한 결과도 동일 화면 해시는 resource 12 하나에서만 발견됐다.
- 현재 근거로는 게임이 별도의 동일 리소스를 읽는 상황이 아니다.

## 재현 및 수정

동일한 편집 PGM을 원본 DAT와 0→1→2 적용 후 DAT 양쪽에 다시 패킹한 결과 resource 12 한글 화면이 정상 생성됐다. 0, 1, 2, 12를 순차 재구성한 뒤 각 결과를 다시 추출해 편집 PGM과 비교했으며 네 리소스 모두 픽셀 단위로 완전히 일치했다.

PS1 엔딩 GUI에 다음 검증을 추가했다.

1. 각 리소스를 패킹한다.
2. 패킹된 DAT에서 해당 리소스를 즉시 다시 추출한다.
3. 편집 PGM과 재추출 PGM의 크기와 모든 팔레트 인덱스를 비교한다.
4. 하나라도 다르면 출력 BIN을 만들지 않고 오류로 중단한다.

GUI에서 다시 적용했을 때 로그에 `[검증 성공] resource 12: 재추출 화면 완전 일치`가 표시되어야 한다.

## 런타임 미반영 원인 추가 확인

초기 PS1 GUI는 `FS2_FILE.DAT` 사용자 데이터만 raw BIN에 재삽입하고 변경된 Mode 2 Form 1 섹터의 EDC/ECC를 갱신하지 않았다. 디스크에서 다시 추출하면 한글 데이터가 존재하더라도 에뮬레이터나 실제 하드웨어의 CD 오류정정 처리에서는 정상적으로 읽힌다고 보장할 수 없다.

GUI를 다음 순서로 수정했다.

1. DAT를 임시 BIN에 삽입한다.
2. 원본 BIN과 비교해 사용자 데이터가 달라진 Mode 2 Form 1 섹터를 찾는다.
3. 각 변경 섹터의 EDC와 ECC P/Q를 재계산한다.
4. 보정이 끝난 BIN만 최종 출력으로 사용한다.

0, 1, 2, 12를 적용한 검증본에서는 16개 섹터(LBA 223~424)를 보정했고 영향 리소스가 정확히 `0,1,2,12`로 확인됐다.
# 정정

이 문서에서 리소스 12를 인게임 엔딩 타이틀의 실제 원본으로 본 판단은 이후 0 타일 진단으로 반증되었다. 최신 결론은 `64-ps1-ending-title-runtime-image-search.md`를 따른다.
