# 그래픽 컨테이너 전수 목록과 글꼴 후보 선별

## 결론

일반 리소스 4,335개를 `12-graphic-payload-and-reconstruction.md`에서 확정한 그래픽 컨테이너 구조로 전수 검사한 결과, **241개**가 헤더·팔레트·타일맵·8bpp pattern 조건을 모두 만족했다.

그러나 작은 높이, 높은 타일 재사용률, 적당한 pattern 수를 기준으로 선별한 상위 후보들은 글꼴 아틀라스가 아니었다. 실제 복원 결과는 다음 세 종류였다.

1. 일본어 문구가 이미 픽셀로 합성된 UI 이미지
2. 배경·인물·효과 애니메이션 시트
3. 로고·버튼·장식용 작은 그래픽

따라서 이 8bpp 그래픽 컨테이너군 안에서 독립적인 일본어 글꼴 아틀라스를 찾는 우선순위는 낮춘다. 대신 UI 번역에서는 사전 렌더링된 일본어 문구도 개별 교체 대상이 된다.

## 전수 검사 조건

리소스가 다음 조건을 모두 만족할 때 확정 그래픽 컨테이너로 분류했다.

- width와 height가 각각 `1..512` tiles
- `payload_offset = align4(0x210 + width × height × 2)`
- `payload_offset + payload_bytes`가 할당 범위 안에 존재
- `(payload_bytes - 0x10) % 64 == 0`
- 모든 tilemap character number가 짝수
- 모든 character number가 payload의 raw 8bpp pattern 범위 안에 존재

결과 파일:

- `output/ss-fs2-graphic-resource-catalog.json`
- 전체 일반 리소스: 4,335개
- 확정 그래픽 컨테이너: 241개
- 확인된 ID 범위: 0..693

ID 분포:

| ID 범위 | 컨테이너 수 |
| --- | ---: |
| 0..99 | 12 |
| 200..299 | 54 |
| 500..599 | 87 |
| 600..699 | 88 |

100번대, 300번대, 400번대와 694 이후에는 이 엄격한 형식을 만족하는 리소스가 없었다.

## 후보 점수

자동 점수는 다음 특징을 사용했다.

- 높이 16 tiles 이하
- 폭 8..64 tiles
- 타일 재사용률 25% 이상
- pattern 수 64..512개
- 폭이 10 또는 16의 배수
- 전체 픽셀 면적이 512×256 이하

이 점수는 조사 순서를 정하기 위한 휴리스틱이며 글꼴 판정값이 아니다. 실제로 최고점 후보 대부분은 애니메이션이나 문구 합성 화면이었다.

## 번역 관점의 의미

UI 문구 일부는 런타임 문자 렌더링이 아니라 그래픽 리소스에 직접 포함되어 있다. 이런 문구는 다음 방식으로 번역할 수 있다.

1. 컨테이너를 BMP로 복원
2. 한국어 문구를 동일한 색수·영역에 렌더링
3. 8×8 tile 단위로 pattern 중복 제거
4. RGB555 팔레트, u16 tilemap, raw 8bpp payload 재생성
5. 원래 할당 크기 안에서 교체하거나 리소스 재배치

특히 ID 0과 1처럼 폭이 긴 문구는 한국어 길이에 따라 tilemap 폭 또는 pattern 수가 달라질 수 있다. 최초 PoC는 같은 canvas 크기를 유지하고 기존 pattern 공간 이내에서 교체하는 편이 안전하다.
