# 엔딩 문구·크레딧 PNG 편집 및 재삽입 GUI

## 대상

다음 SS 리소스만 고정 대상으로 사용한다.

```text
0, 1, 2, 11, 12, 14, 15, 16, 18, 19, 20, 21
```

- `0`: 어디로 가고 싶습니까?
- `1`: 엔딩 선택지 두 줄
- `2`: 현재의 어트랙터로...
- `11`: 기획·개발·판매
- `12`, `16`, `18~21`: 엔딩 크레딧
- `14`, `15`: 음성 성우 캐스팅

## 실행

```powershell
python tools/ss_fs2_ending_resource_gui.py
```

기본 입력은 최종 빌드된 다음 파일이다.

```text
output/ss-fs2-korean-final-track1.bin
```

이 도구는 final patch builder에 포함되는 전처리가 아니라 최종 빌드 BIN을
다시 수정하는 후처리 도구이다.

## 작업 순서

1. `1. 편집 PNG 추출`을 누른다.
2. 작업 폴더에서 `ss-fs2-resource-<ID>.png`를 확인한다.
3. 편집할 파일을 `ss-fs2-resource-<ID>-ko-edit.png`로 복사한다.
4. PNG 크기를 바꾸지 않고 일본어를 지운 뒤 한글 이미지를 그린다.
5. `2. -ko-edit.png 자동 적용`을 누른다.

적용 버튼은 존재하는 `-ko-edit.png`만 자동으로 찾는다. 선택된 리소스 중
편집 파일이 없는 항목은 건너뛴다.

## 팔레트 처리

두 가지 리소스 형식을 자동으로 구분한다.

- `0~2`, `11`: 리소스 내부 RGB555 팔레트 256색
- `12`, `14~16`, `18~21`: 외부 팔레트형이며 raw index `0`, `1`, `2` 사용

외부 팔레트형 편집 PNG에서는 다음 확인색을 쓴다.

- index 0: 검정 배경
- index 1: 회색 경계선
- index 2: 흰색 문자

재삽입 시 PNG 색을 가장 가까운 유효 팔레트 인덱스로 변환한다. 수정하지
않은 픽셀은 RGB가 동일한 경우 원래 인덱스를 그대로 유지하므로 팔레트의
동색 엔트리 때문에 인덱스가 바뀌지 않는다.

## 안전 검사

- 입력 BIN과 출력 BIN을 분리한다.
- 편집 PNG 크기가 원본과 다르면 중단한다.
- 재구성에 필요한 고유 타일 수가 리소스 용량을 넘으면 중단한다.
- raw Mode 1 sector를 기록할 때 EDC/ECC를 다시 계산한다.
- 출력 후 `ss-fs2-verify-patched-bin.js`로 전체 변경 범위를 검사한다.
- Track 2를 참조하는 CUE와 JSON 보고서를 함께 생성한다.

## 검증

대표 두 형식으로 무편집 왕복 시험을 수행했다.

- resource 0: `changedPixels=0`
- resource 14: `changedPixels=0`

전체 12개 대상도 PNG 추출에 성공했다.

## 리소스 0 타일맵 정렬 수정

resource 0은 `37x3=111`개의 16비트 타일맵 엔트리를 가진다. 타일맵
크기 `222`바이트 뒤에 2바이트 정렬 패딩이 있으므로 다음 역산은 틀린다.

```text
tileMapOffset = tileDataOffset - 222
```

이 계산은 실제 `0x210` 대신 `0x212`를 반환해 첫 엔트리를 건너뛰고
문장 앞부분을 뒤로 밀었다. 파서는 이제 다음 두 형식을 4바이트 정렬까지
포함해 판별한다.

- 내장 팔레트형: `align4(0x210 + mapBytes) == tileDataOffset`
- 무팔레트 엔딩형: `align4(0x10 + mapBytes) == tileDataOffset`

수정 후 resource 0 문장 전체 순서와 무편집 왕복 `changedPixels=0`을
다시 확인했다.
